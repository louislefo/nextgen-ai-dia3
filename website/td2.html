TD 2: Majority Voting Consensus & Dynamic Routing

Designing robust decision mechanisms for production AI systems: combining multi-model voting quorums for critical queries with dynamic rule-based model routing to minimize operational costs.

Building on TD 1 Empirical Findings

TD 1 revealed that lightweight models achieve near-perfect accuracy (96.7% to 100%) on timestamp and product filters, but drop to 60.0% on completed age arithmetic. TD 2 exploits this gap to build an automated, cost-optimal system.

1. Pillar 1: Majority Voting Consensus (k-of-n Quorum)

When a database query carries operational or financial consequences, trusting a single probabilistic model draw is unacceptable. The voting consensus mechanism operates as follows:

Mechanism

Parallel Panel Querying

A query is simultaneously dispatched to n distinct models (e.g., n = 3 or 5). To ensure true independence, the panel must not reuse duplicate backend providers or shared model families.

Verification

Sandboxed Execution & Value Matching

Model SQL queries are executed independently in the SQLite read-only sandbox. Votes are cast on the computed numerical revenue (revenue_cents), not on verbatim SQL string similarity.

Safety Guardrail

Quorum Threshold & Abstention

If at least k models agree on the identical value (e.g., 2 out of 3, or 3 out of 5), that value is accepted. Otherwise, the system safely abstains rather than outputting a hallucinated figure.

2. Pillar 2: Dynamic Difficulty Routing

Instead of sending all questions to expensive frontier models, a pre-inference rule inspects request complexity and selects the cheapest model capable of reliable answering:

Query Complexity Tier Question Characteristics Routing Decision Economic Rationale
Tier 1: Simple Period / Product Orders between dates, product categories (C01, C03, C04, C05, C07, C12, C13, C20). Route to Tier 1 Compact Model (e.g., GPT-OSS 20B or Dots). Near 100% accuracy at zero / minimal token cost.
Tier 2: Complex Boundary / Age Exact completed age at order time or reference date (C02, C08-C11, C15-C19). Route to Frontier Model (GPT-120B) OR 3-Model Voting Panel. Prevents severe calendar date miscalculations identified in TD 1.

3. TD 2 Workshop Modules

atelier-vote.py

Harness for testing the quorum voting algorithm across four key operational edge cases:

  • Consensus agreement: Models return matching values; quorum met.
  • Consensus disagreement: Models diverge; verified safe abstention.
  • Provider outage (HTTP 429/timeout): Graceful quorum degradation.
  • Duplicate routes: Detecting and rejecting false consensus from duplicate models.

atelier-routage.py

Benchmarking harness evaluating the routing rule against seven distinct real-world traffic scenarios, balancing accuracy against total API expenditure.
